# 12 · 引擎引用审计：「AI 为什么没有引用我们」

> 最直接的 GEO 效果检验：**向引擎提一个买家意图问题，看它引用了谁，再诊断为什么没有你。**
> 这个审计工作流，正是那个经典结论背后的方法论：「豆包引用了竞品却没引用我们——因为中文内容生态里根本没有我们的提及」。

## 1. 双门槛模型（被检索到 ≠ 被选中引用）

动手前先判断你卡在哪个门槛。两者的修法完全不同，搞混会浪费几个月：

```
门槛 1：检索（retrieval）——引擎到底有没有把你当作候选？
门槛 2：选择（selection）——你进了候选池，为什么没选你？
```

| 门槛 | 问题 | 失败症状 | 真正有效的修法 |
|---|---|---|---|
| **1. 检索** | 品牌/页面在不在引擎的候选集里？ | 回答里完全没提你 | 内容生态存在感：第三方提及、教程、评测、讨论（**不是你的官网**） |
| **2. 选择** | 你被检索到了，为什么没被引用？ | 提到你了，但引用全给竞品 | 页面级可引用性：可引用段落、权威信号、结构化数据、对题性 |

> **最常见的错误**：一个官网做得很好却从没被引用的品牌，会认为是官网坏了。
> 通常是官网**没问题**——只是品牌根本不在检索候选集里，因为**开放互联网上没人写你。**
> （见 `11-cn-geo-playbook.md` 第 1 节：官网只占国内 AI 引用的 1.37%——官网是事实源，不是引用源。）

## 2. 五步审计流程

### 第 1 步 · 定义问题集

选 5–10 个**买家意图**问题（推荐 / 比较 / 替代 / 价格）——离成交最近，也最值得打。用真实用户问法，不要翻译腔：

- 中文：「AI 记忆产品有哪些好用的？」「Mem0 和 Mem.ai 哪个好？」「给 AI 加记忆的工具」
- 英文："What's the best AI memory tool in 2026?" "Mem0 vs Mem.ai comparison"

每题标 `market`（cn / global）——中文题路由到国内引擎，英文题路由到海外。

### 第 2 步 · 跑引擎（记录环境）

不记录环境，样本就是废的（证据分级，见 `11-cn-geo-playbook.md` 第 7 节）：

| 环境 | 含义 |
|---|---|
| API 联网（grounding 开启） | 真实检索，可复现 |
| API 不联网 | 只测参数化知识——测的是品牌认知，不是可见性 |
| 网页 / App，新开对话 | 真实用户样本，记录环境（无痕/专用 Profile）为 A 级 |

规则：每题**新开对话**，不连续追问（上下文会带偏置）；复制完整答案原文（含引用链接）；
**"没提到品牌"也要记录——那是最重要的数据。**

### 第 3 步 · 记录发生了什么

每条答案记录：

1. **引用了哪些来源**（域名 + 标题）——这就是当下的真实分发地图
2. **你的品牌在哪**：被提及+被引用 / 只被提及 / 完全没出现
3. **若被提及，描述准确吗？**（行业对、事实对、措辞对）
4. **引用位置**——你在第一个、中间、还是缺席

### 第 4 步 · 用决策树诊断

```
你的品牌出现在答案里了吗？
├─ 没有 → 你卡在门槛 1（检索）
│   └─ 为什么？内容生态零提及。
│       → 检查：在引擎读的那些平台上搜「品牌 + 品类」有结果吗
│         （国内：知乎 / CSDN / 掘金 / 公众号 / 网页；海外：Reddit / YouTube / 博客）？
│       → 修法：内容生态建设（第 4 节），不是官网工作。
├─ 提到了，但引用全给竞品 → 过了门槛 1，卡在门槛 2（选择）
│   └─ 为什么？可检索，但被引页面在段落质量/权威上赢你。
│       → 检查：你的页面有没有可引用段落（≥60 词 + 硬信息，见 `03` §8.5）？
│         权威信号（日期、作者、外部引用）？结构化数据？对题的 H1/H2？
│       → 修法：页面级可引用性（`03` 证据页骨架）、权威（`05`）。
└─ 提到了，但描述是错的（行业错 / 事实错 / 措辞错）
    └─ 可检索，但你的实体表征不一致。
        → 修法：品牌事实卡 + JSON-LD 逐字一致（`05` 第 7 节）——AI「品牌漂移」的头号原因。
```

### 第 5 步 · 行动 + 复测

优先级（与 `11-cn-geo-playbook.md` 第 6 节合并）：

1. **P0——自有站的检索阻断**：robots/WAF 封禁、SPA 空壳、无 sitemap、无结构化数据（见 `04`）
2. **P1——内容生态**：审计暴露出的具体缺口——教程、评测、社区讨论、榜单站收录
3. **P1——页面可引用性**：针对可检索的页面（证据页骨架，`03` §8.6）
4. **P2——长尾扩量**

改完复测同一组 5–10 个问题（生态建设每周看一次，完整周期至少每月一次）。
追踪：提及率、首次出现位置、引用份额变化。

## 3. 竞品被引用、我们没有——事后复盘

当引擎引用了竞品而从不引用你，去读被引的那些内容，逆向拆解它们赢在哪：

| 竞品有什么 | 在哪里 | 证明了什么 |
|---|---|---|
| 产品主页 + 大量评测（中英文内容生态） | 第三方评测站、博客 | 它们在国内国外两个市场都进了检索池 |
| 开源标准 + 大量教程（GitHub 高 star + 中文教程多） | CSDN / 掘金 / GitHub / 文档 | 教程内容 = 品牌提及密度 = 检索胜出 |
| 中文社区 / 开源项目 | 知乎 / 社区 | 母语存在感 > 网站语言 |
| 硬件评测（电商 + 评测文） | 电商站、评测博客 | 评测就是伪装成引用的品牌提及 |

**规律**：每个被引的竞品都有一条**第三方内容足迹**。实时 RAG 的引擎只能引用候选池里的内容，
而候选池是由开放网页上的提及堆出来的，不是你的官网。官网是**事实锚点**，生态才是**引用源**。
（1.37% 法则，`11` 第 1 节。）

## 4. 内容生态建设清单（门槛 1 的修法）

| 渠道 | 要创造的内容 | 谁会读它 |
|---|---|---|
| **教程**（国内：CSDN / 掘金；海外：Dev.to / Medium） | 「怎么给 AI 应用加记忆」——审计里竞品正在用同款教程赢的内容 | 豆包（字节生态）、千问、DeepSeek、ChatGPT |
| **社区讨论**（国内：知乎；海外：Reddit / HN） | 真实回答问题，自然带出产品，不硬广 | Perplexity（Reddit 占 46.7%）、豆包、Kimi |
| **第三方评测 / 对比** | 找评测者；对比文（"A vs B"）用同口径表格 | 所有引擎——对比页是最有价值的 GEO 资产 |
| **榜单 / 目录站**（国内：买购网 / 品牌网 / 中国品牌网；海外：G2 / Capterra） | 入驻上榜——AI 最爱抄现成榜单 | 跨平台通吃（见 `11` 第 5 节） |
| **官网** | 只当事实锚点：定义、事实、结构化数据、统一措辞 | 没人直接引用它，但所有提及最终都链到它 |

**纪律**：
- 每篇生态内容必须链回官网（事实锚点），品牌名/拼写保持一致。
- 不同渠道**不要发完全相同的内容**——同样的事实，每个平台换一种形态（一稿多投规则）。
- 绝不买或伪造提及；做真教程、真评测。被检测和惩罚的风险不值得。
- **没有官网也能做**（电商商品、小程序、线下品牌）：生态建设照常跑——AI 可见性本来就主要靠外部阵地（`11` 第 1 节）。

## 5. 豆包专项

豆包 = 字节生态。检索池高度偏向字节系内容：

- **抖音图文/视频是主入口**（iesdouyin.com 占豆包 App 引用 28.1%——见 `11` 第 2 节）
- 头条号次之；公众号主要服务腾讯元宝，不是豆包
- 豆包 App 和 web 信源池不同——分开采样（Jaccard 约 47% 重合）
- API 注意：豆包 `/responses` + web_search 需要在火山方舟控制台单独开通内容插件；
  不联网的 API 只测参数化知识（证据等级：离线 B 级，不是 A 级）

**用户侧要解决的是内容生态建设；技术侧能做的只是最大化「一旦被检索到就能被引用」——但先要进入候选集。**

OpenHuman / Obsidian+Engram——我们的品牌缺席，因为中文内容池里没有任何关于我们的提及。*
