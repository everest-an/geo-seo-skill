# 03 · 内容与引用优化

> 核心问题：AI 引擎为什么**引用** A 而不是 B？
> 答案：**可提取性（extractability）+ 信息增益（information gain）+ 可信度（trust）**。

## 1. 最容易被 AI 引用的内容类型

| 内容类型 | 为什么被引用 |
|----------|--------------|
| **原创研究/数据** | 提供可支撑具体论断的独家证据 |
| **案例研究** | 支撑 AI 的具体推荐 |
| **权威定义** | 易提取、可直接引用 |
| **步骤式指南** | 可操作、高价值 |
| **对比表格** | 结构化信息，AI 直接拿来用 |
| **FAQ / Q&A** | 直接回答，天然可提取 |
| **思想领袖观点** | AI 想引用独特多元视角 |
| **新闻/时效内容** | 预训练数据无法覆盖近期事件 |
| **品牌自有内容** | AI 认为品牌对自身信息最权威 |

**不适合 GEO 的内容**：薄内容、重复内容、纯销售文案、无来源观点、过时信息。

## 2. 信息增益（Information Gain）—— 排名提权的关键

**定义**：你的页面相比搜索引擎已收录的 Top 结果，提供了多少**新增、独特**的信息。

**做法（对应四步法第一步）**：
1. 拉取目标关键词的 Top 5–10 竞品。
2. 提取共识信息 + 差异化卖点 + 盲区（见 `02-rapid-method.md` 的指令）。
3. 只补"盲区"——独特数据、独家案例、未覆盖的角度。
4. 结果：语义系统判定你"信息增益"更高 → 提权信号。

**反向警示**：只复制共识信息 = 零增益 = 无排名动力。

## 3. 可提取性（Extractability）—— "AI 最爱格式"

让 AI 一行代码就能抓出你的核心结论：

- **问题式标题层级**：H2/H3 直接写成用户会搜的问题（"什么是 X"、"X 要多少钱"）。
- **每段 2–3 句**：避免长文本块，NLP 更易解析。
- **关键结论用列表/表格**：定义、数据、对比 → 列表或表格。
- **前部"快速导航区"**：TL;DR + 直接回答 5 个最可能的追问。
- **可独立成句的"引用句"**：一句话就能被摘走引用（quotation-worthy）。
- **明确来源与日期**：AI 需要判断可信度与新鲜度。

## 4. 语义与实体（LSI / 同义词）

- 自然嵌入同义词变体（LSI 关键词），密度 **2–3%**（不堆砌）。
- **实体覆盖**：围绕主题覆盖相关实体（人、组织、概念、产品），提升语义相关性（RAG 检索因子中语义相关性权重最高 ~40%）。
- 关键词填充是反效果——GEO 论文明确证实。

## 5. FAST 框架（AI 可抓取性体检）

> 来源：Semrush「Why Site Health Is Vital For AI Search Visibility」

| 维度 | 问题 | 关键动作 |
|------|------|----------|
| **F - Fetchable（可抓取）** | AI 能否在不渲染 JS 的情况下读取 HTML？ | 关 JS 测试页面；核心信息放初始 HTML；SSR |
| **A - Accessible（可访问）** | 不执行脚本能否理解内容？ | alt 文本、H1–H6 层级、语义化 HTML5 |
| **S - Structured（结构化）** | 是否用了 Schema、语义标签、清晰层级？ | 定义框、Product/Article/Organization Schema、FAQ Schema |
| **T - Trim（精简）** | 是否只发送必要内容、无噪音？ | 清理追踪脚本、压缩资源、精简 JS 依赖 |

> **速测**：把你 Top 20 页面在禁用 JavaScript 的浏览器里打开——你看到什么，AI 爬虫就大约看到什么。

## 6. GEO 内容检查清单

**内容元素**
- [ ] 问题式标题
- [ ] 顶部摘要/TL;DR
- [ ] 原创数据（带来源）
- [ ] 专家引语（姓名 + 头衔）
- [ ] FAQ 区块（3–5 个 Q&A）
- [ ] 清晰定义
- [ ] "最后更新"时间戳
- [ ] 作者 + 资质

**结构元素**
- [ ] 含日期的 Article Schema
- [ ] 作者的 Person Schema
- [ ] FAQPage Schema
- [ ] 加载速度 < 2.5s
- [ ] 干净的语义化 HTML

## 7. 可引用性评分框架（借鉴自 claude-seo）

> 一套加权审计模型——给任何页面打 0–100 分，评估 AI 引擎凭什么选它。

| 维度 | 权重 | 检查要点 |
|------|------|----------|
| **可引用性** | 25% | 134–167 词的自包含答案块；前 40–60 词内给出直接答案；具体事实/统计；标注来源的论断；"X 是…"定义句式 |
| **结构可读性** | 20% | 清晰的 H1→H2→H3 层级；问题式标题；2–4 句短段落；表格与列表；FAQ 问答块 |
| **多模态** | 15% | 文本 + 图片、视频、图表、互动工具；为媒体配结构化数据（多模态内容被选率提升 **156%**） |
| **权威与品牌** | 20% | 作者署名 + 资质；发布/更新日期；一手来源引用；Wikipedia/Wikidata 实体存在；Reddit/YouTube/LinkedIn 提及 |
| **技术可达性** | 20% | SSR（AI 爬虫不执行 JS）；robots.txt 放行 AI 爬虫；llms.txt 存在；结构化数据 |

**杠杆最高的数字：**

- 最优可引用段落：**134–167 词**
- **约 44%** 的 AI 引用来自页面**前 30%** 的内容 → 把答案前置，别埋在折叠线以下
- **92%** 的 Google AI Overviews 引用来自排名前 10 的页面，但 **47%** 来自第 5 名以后的页面 → 传统排名 ≠ 引用选择
- 新鲜度：发布 3 个月内的内容被引用概率**约 3 倍**；停滞 6 个月以上的页面失去引用资格 → 安排定期刷新
- **品牌提及与 AI 可见度的相关性约是外链的 3 倍**（Ahrefs 7.5 万品牌研究）：YouTube 提及 r≈0.737（最强）、Reddit 高、Wikipedia 高、LinkedIn 中等；域名评级（DR）仅 r≈0.266

## 8. 分平台引用来源

AI 引擎引用的是**不同的来源池**——按平台分别优化：

| 平台 | 主要引用来源 | 优化重点 |
|------|--------------|----------|
| **Google AI Overviews** | 与排名强相关（引用已经排名靠前的页面） | 传统 SEO + 段落优化 |
| **Google AI Mode**（基于 Gemini 2.5） | 与排名弱相关；每次查询约引用 9 个域名 | 新鲜度、实体权威、第 5 名之外的可引用段落 |
| **ChatGPT** | Wikipedia（47.9%）、Reddit（11.3%） | 实体存在、权威来源 |
| **Perplexity** | Reddit（46.7%）、Wikipedia | 社区验证、讨论存在感 |
| **Bing Copilot** | Bing 索引、权威站点 | Bing SEO、IndexNow |

> **谷歌有两个引用引擎，不是一个。** AI Mode 与 AI Overviews 约 86% 的情况下结论一致，但只有 **13.7%** 的引用 URL 重合（Ahrefs 研究，54 万组查询对）。把它们当作两个独立阵地。
>
> **只有 11% 的域名**在同一查询中同时被 ChatGPT 和 Google AI Overviews 引用——别指望一个页面处处通吃。

## 9. 反模式

| ❌ 不要 | ✅ 要 |
|---------|-------|
| 无日期发布 | 加时间戳 + dateModified |
| 来源含糊 | 明确标注来源 |
| 跳过作者信息 | 展示资质与经验 |
| 薄内容 | 全面深度覆盖 |
| 关键词堆砌 | 语义 + 实体 + 信息增益 |
| 诗意模糊语言 | 直白、可独立成句的表达 |
